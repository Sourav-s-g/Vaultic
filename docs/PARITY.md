# Vaultic Web Parity Audit

This document records the Phase 0 audit of Flutter behavior and the user's approved decisions for the web implementation. Flutter references are the source of truth; where code is missing, unreachable, internally inconsistent, or dependent on external Supabase configuration, that is called out rather than inferred as implemented behavior.

## Scope And Repository Constraints

- Reviewed `lib/` entry/auth/dashboard/screens/widgets/models/services/config, including `main.dart`, auth forms and gate, `HomePage.dart`, all screen files, `QuickAddBar`, storage and Supabase services, the smart input parser, and PDF generation.
- The authoritative checked-in snapshot is [`docs/supabase/schema-snapshot.md`](./supabase/schema-snapshot.md). It records constraints, columns, RLS status and policies for seven tables. `public.delete_user_account()` is retained in the snapshot but remains out of scope for the web app.
- Root `web/` remains Flutter's web target (`index.html`, `manifest.json`, `icons/`, `splash/`, and `.github/`). The Next.js app is now separately scaffolded in `web-app/`; Flutter's target was left untouched.
- `web-app/src/types/database.types.ts` reflects the checked-in snapshot’s column names, nullability, defaults and constraints. The actual web inserts still explicitly set authenticated `user_id` for tables where it is nullable.
- There is no `providers/` directory or separate app-wide provider layer in `lib/`. State and data orchestration live in screen state and static storage/service classes.

## Transaction Date Serialization

Flutter's transaction date picker constructs local `DateTime` values. `HomePage._showAddTransactionDialog`, `TransactionHistoryScreen._showEditDialog`, and `CategoryTransactionsScreen` serialize them with `DateTime.toIso8601String()`; local `DateTime` serialization has no UTC offset. `Transaction.fromJson`, `HomePage._transactionFromMap`, and the history mapping use `DateTime.tryParse` and do not call `toLocal()` or `toUtc()`. The web date-only form therefore serializes the selected calendar day as `YYYY-MM-DDT00:00:00.000` with no offset, matching Flutter's local-wall-time string convention. When Supabase returns a timestamp with an offset, the web derives the same calendar fields Flutter derives from that parsed instant and never parses a date-only value with JavaScript's UTC date-only interpretation.

## Balance, Money, Date, And Sync Semantics

- Transactions and balances are represented as Dart `double`; UI generally rounds to whole rupees, while statement currency prints two decimal places. There is no integer-minor-unit or decimal-string invariant in the app source.
- Initial balance is local preference `vaultic_initial_balance_v1` and optionally `user_settings.initial_balance`; missing `user_settings` results in cloud initial balance `null`/zero in authenticated mode.
- Month-end balance starts at initial balance, sums non-carry-forward credits minus debits through the target month. A positive result creates a next-month `Credit` transaction described `Balance carried forward from <Mon YYYY>`; negative creates an unsettled `owe` OWO entry. The helper is excluded from fresh cumulative calculations by a flag/description check.
- Rollover is called at startup and after non-carry-forward transaction add. Local `vaultic_processed_months_v1` plus description/ID scanning is used for dedupe. This is not a database-atomic idempotency guarantee: two devices/tabs can race, processed-month state is local, IDs include current milliseconds, and no unique constraint/RPC is evidenced. Implementing the user's required cross-client idempotency may require a server-side atomic contract, but Phase 0 does not authorize a schema change and the present RPC contract is unknown.
- Offline-first categories/transactions/budgets/OWO use SharedPreferences; transactions and OWO queue failed writes and expose pending state. Categories and budgets do not have a comparable queued mutation log. Trips use a separate cache; remote nonempty data is merged with local data and wins matching IDs. Cloud reads often fall back silently to local values.
- Dates are stored through `DateTime.toIso8601String()` and compared using local calendar components in parts of the UI. The data contains no declared timezone contract. Browser date-only filtering and timestamp serialization need explicit timezone-safe semantics; don't reinterpret a local date as UTC or let timezone shifts change transaction day/month.

## Unimplemented, Dormant, Or Conflicting Behavior

1. **OTP mismatch:** Phase 2 asks for OTP sign-in/up; current Flutter auth is email/password plus email-confirmation and password recovery. No OTP contract can be inferred. Reconcile desired OTP with current Supabase Auth settings before treating it as parity.
2. **Existing `web/` collision resolved:** root `web/` remains the Flutter platform target; Next.js now lives in `web-app/`.
3. **Backend contract absence:** table DDL, migrations, constraints, and RLS policies are missing. The SQL function in the snapshot is used only by Flutter and is not part of the web app. Actual table types/constraints and safe data operations cannot be certified from client code. No migration is justified by this audit alone.
4. **Bank linking:** `bank_connection_screen.dart` is intentionally empty/deprecated; no bank integration service was found. Bank-link claims in legal copy are not proof of a feature.
5. **Unreachable UI:** `DataRecoveryScreen`, `TermsScreen`, and standalone `QuickAddBar` have no app call sites. The dashboard uses a separate embedded OWO component. Include these only as explicitly identified parity gaps/optional routes, not as confirmed active flows.
6. **PDF provider mismatch:** the active report path is local Dart PDF generation with an embedded Noto font; the HTML/PDFShift client path exposes a provider secret if configured, and the Adobe path has placeholder credentials. A web PDF must run server-side and preserve the rupee glyph; there is no currently verified hosted provider/secret contract.
7. **Category deletion and budgets:** deletion is name-based, historical transactions hold category text, and remote budget deletion is missing. Preserve ledger history and safely remove/retire category references; do not cascade-delete transactions. Validate actual table constraints and decide whether stale budgets must be deleted server-side.
8. **Meaningful existing inconsistencies:** all-debit/category detail labels and projections use all-time data; partial OWO payment can post more than outstanding debt; selected-period PDF opening balance is inaccurate; cloud recovery omits trips/initial balance; cache clear omits some local keys; and backup inspection uses a legacy key. Web should implement financially correct outcomes rather than reproduce these defects, while retaining the user's requested capabilities.

## Approved Decisions

These decisions were approved for Phase 1 and later implementation. Every fix or omission that changes Flutter behavior is recorded under `Intentional Changes` below.

- **Folder and auth:** The Next.js application lives in `web-app/`; root `web/` remains Flutter's web platform folder. Authentication uses email/password; no OTP.
- **Money validation:** Amounts must be greater than zero wherever entered, including transaction, budget, debt, and payment amounts. This corrects Flutter forms that accept zero, negative, malformed, or silently defaulted amounts.
- **Transaction deletion:** Ask for confirmation before deleting a transaction.
- **Period totals:** “This Month Spent” and category totals default to the current month and offer an All time switch. This corrects Flutter detail totals that use all dates despite current-month labels.
- **OWO payments:** Cap partial payments at the remaining amount. Reopening a settled entry warns that its earlier settlement transaction remains; do not silently reverse that transaction.
- **PDF dates and balance:** Date-range end is inclusive through the end of that calendar day in the selected user timezone. Compute the opening balance from all transactions before the selected start date. This corrects Flutter's midnight end-boundary and all-time-initial-balance behavior.
- **Monthly summaries:** Monthly net and month details consistently exclude carry-forward helper rows, as do summaries.
- **Category deletion:** Removing a category never deletes or rewrites transaction history. Delete the matching category row and its budget row scoped by the authenticated `user_id` and category key/name.
- **Category colors:** Use one stable mapping for dashboard, history pie, trips, and PDF. The ten suggested categories retain their audited suggested colors. Custom categories use deterministic FNV-1a of the name mapped into the audited dashboard palette. Do not use Dart `hashCode` behavior.
- **Online-first and query state:** Supabase is the source of truth. TanStack Query provides caching, invalidation, optimistic updates, and rollback. Do not build an offline mutation queue; “Sync now” becomes Refresh.
- **Backup behavior:** Replace device-local backup management with JSON download and JSON import that merges only records absent by `transaction_id` / `owo_id`; preview inserted/skipped counts and request confirmation, never replace existing records. Omit local auto-backup history and the DataRecovery screen.
- **Trips:** Use per-row insert/update/delete scoped by `(user_id, transaction_id)` rather than delete-all-then-reinsert. Edit trip transactions in place and preserve status/split fields.
- **Dormant Flutter surfaces:** Do not port the standalone `QuickAddBar` or deprecated `BankConnection` screen. Port `/privacy` and `/terms` as static pages with Flutter copy as-is, and retain the external privacy URL link in Settings. Unverified bank-linking, biometrics/MFA, encryption, and compliance claims are listed in `docs/OPEN-ITEMS.md`.
- **Account deletion:** Omit account deletion from the web app entirely; do not show a disabled control, call the incomplete RPC, or provide a client-side alternative.
- **Carry-forward:** Use deterministic Credit `transaction_id` `carry-forward-YYYY-MM` and description `Balance carried forward from <Mon YYYY>`. Before insert, check both that ID and the target month's description because Flutter used different IDs. Negative balance produces an `owe` entry with `owo_id` `carry-forward-owe-YYYY-MM`. Run rollover under `navigator.locks`. Propose, but do not apply, a unique `(user_id, transaction_id)` index in `supabase/migrations/` only after verifying table definitions and existing duplicates in the snapshot.
- **Paise arithmetic:** Supabase `amount` columns are numbers. Parse user input to integer paise, perform arithmetic in paise, and serialize as a number with at most two decimal places.

### Intentional Changes

- Require amounts greater than zero for all monetary inputs, reject non-finite values, and perform calculations in integer paise.
- Reject invalid transaction edit amounts with a visible validation error instead of silently retaining the prior amount.
- Reject blank or case-insensitive duplicate category names after trimming, including unsaved setup selections.
- Require confirmation before deleting a transaction.
- When removing a category, delete only its category and matching budget rows scoped to the authenticated user; preserve every transaction's stored category text.
- Compare a transaction's loaded `updated_at` on edit and show a conflict/reload path instead of silently overwriting a concurrent change.
- Default “This Month Spent” and category totals to the current month, with an All time switch.
- Cap OWO partial payment/receipt at the remaining amount; warn when reopening a settled entry because its settlement transaction remains.
- Make PDF end dates inclusive through end-of-day and calculate opening balance from all transactions before the selected range.
- Exclude carry-forward helper rows consistently from monthly net, month details, and summaries.
- Use a single deterministic category palette across dashboard, history pie, trips, and PDF; use FNV-1a for custom categories rather than Dart hash codes.
- Use online-first Supabase mutations with TanStack Query optimistic updates/rollback and no offline mutation queue; convert “Sync now” to Refresh.
- Replace local backup/auto-backup history and DataRecovery with confirmed JSON export/download and merge-only import showing inserted/skipped counts.
- Use row-level trip-transaction mutations and preserve status/split fields when editing.
- Do not port the standalone QuickAddBar or deprecated BankConnection screen.
- Do not port account deletion to the web app.
- Persist category `color` and `icon` in web category rows. Flutter's setup and category-management screens save only category names, so retaining the audited color/icon metadata in the database is a deliberate web behavior change.
- Serialize a selected web transaction calendar date using Flutter's offsetless local `toIso8601String()` convention (`YYYY-MM-DDT00:00:00.000` for the date picker); use wall-calendar fields to avoid timezone shifts changing the selected day.
